# Agricultural data foundation

This prototype adds an offline, reproducible pipeline for regional yield baselines and a sourced crop-requirement reference. It does not change the user interface or feed new values into the Planning Engine.

## Integrated sources and coverage

### Maharashtra area and production

The source is the National Horticulture Board (NHB), *Horticultural Statistics at a Glance 2018*, with the state-wise tables credited in the report to the Horticulture Statistics Division, Department of Agriculture, Cooperation and Farmers Welfare:

- Maharashtra, green chilli: table 7.3.25, printed page 194.
- Maharashtra, okra: table 7.3.27, printed page 195.
- Maharashtra, tomato: table 7.3.34, printed page 203.
- Crop years: 2015–16, 2016–17, 2017–18.
- Reported units: area in thousand hectares and production in thousand metric tonnes.

The source is [the NHB publication PDF](https://nhb.gov.in/statistics/Publication/Horticulture%20Statistics%20at%20a%20Glance-2018.pdf). Its tables do not specify whether each annual value is a final or advance estimate and do not provide a season split. The values are Maharashtra state totals, not district or farm observations.

### Crop environment references

The pipeline also imports three FAO ECOCROP data sheets:

- Okra (*Abelmoschus esculentus*), ECOCROP 289: [FAO data sheet](https://ecocrop.apps.fao.org/ecocrop/srv/en/dataSheet?id=289).
- Tomato (*Lycopersicon esculentum*; synonym listed as *Solanum lycopersicum*), ECOCROP 1379: [FAO data sheet](https://ecocrop.apps.fao.org/ecocrop/srv/en/dataSheet?id=1379).
- Green chilli mapped to the species *Capsicum annuum*, ECOCROP 618: [FAO data sheet](https://ecocrop.apps.fao.org/ecocrop/srv/en/dataSheet?id=618).

The reference records include optimal and absolute temperature, annual rainfall and pH ranges, soil texture/drainage/depth, and crop-cycle days. FAO describes ECOCROP as a global crop database and says the original database was discontinued around 2015 and is now accessible through GAEZ. These records are global species envelopes, not Maharashtra, variety, or season recommendations. Annual rainfall is not irrigation demand; the source sheets do not specify irrigation requirements. Use these fields only for crop screening, not yield estimation or economic ranking.

The NHB report footer states NHB copyright; no separate open-data license or reuse terms were located. FAO website terms allow copying for private study, research, teaching, and non-commercial products or services with acknowledgement; commercial use, adaptation, or resale requires permission. No ECOCROP-specific open-data license was identified. See the [FAO terms](https://www.fao.org/contact-us/terms/en/) and review both sources before broader or commercial reuse. The repository includes small attributed factual extracts. Access dates and limitations are in data/agriculture/source-manifest.json.

## Reproduce and validate

No credentials, network access, database, or third-party Python packages are needed. The pipeline requires Python 3.10 or later. The two CSVs are offline import snapshots of the cited NHB table rows and FAO ECOCROP data sheets.

~~~sh
python3 scripts/build_agricultural_data.py
python3 scripts/build_agricultural_data.py --check
python3 -m unittest discover -s tests -v
npm test
npm run build
~~~

The script reads data/agriculture/source/nhb-maharashtra-2018.csv, data/agriculture/source/fao-ecocrop-requirements.csv, and data/agriculture/source-manifest.json, then writes src/data/agriculturalBaselines.json. The check option compares generated bytes with the committed output. To update a source, review its release, retain original units and status, update the manifest and source extract, then regenerate. Missing cells stay null and are never filled with an undocumented value.

## Output and methods

The JSON artifact contains:

- Region, crop-year, crop, unit, source, table/page, and access-date metadata.
- Source-reported area and production in normalized hectares/acres and tonnes/kilograms.
- Derived annual yield in kg/hectare and kg/acre.
- Per-crop sample counts, observed and missing years, min/median/max/mean, coefficient of variation, and consecutive-year changes.
- FAO crop environment references with their global scope, optimal/absolute ranges, explicit unknown fields, and source provenance.
- Named planning reference values: conservative is the minimum supported annual yield; expected is the median. The highest historical value is descriptive only, not a forecast.

Data categories are kept explicit:

| Category | What it means here |
| --- | --- |
| Source-reported statistics | NHB area and production values; the report does not state final/advance status. |
| Derived statistics | Annual yields, historical summaries, and the named conservative/expected references calculated from those values. They are not forecasts. |
| Agronomic reference | FAO global species-level environment ranges for screening; not locally validated recommendations. |
| Synthetic demo data | Existing crop profiles, buyer orders, market signals, farmer/plot records, and farm-reported conditions. |

The yield history is only three years and the publication is old. It has no season or district distinction. These regional values are not farm-level predictions. No historical wholesale prices, actual buyer procurement demand, local weather, soil test or independently evaluated forecast is integrated. The output makes no INR price conversion because it contains no market-price series.

## Planning Engine adapter

src/data/agriculturalEvidence.ts provides typed access to regional yield, crop-requirement references, historical market context, and optional farm conditions. Global FAO references are returned with status reference_only. Data not integrated is returned with an unavailable status. Buyer demand is explicitly labelled synthetic demo input.

The adapter is read-only and is not imported by the current planner. A later integration can call getAgriculturalPlanningEvidence(cropId), map only the named conservative and expected yield references into planner inputs, and retain the source and quality metadata with each plan. Do not map the highest historical year into a future “good season” forecast without a separately justified method. Do not treat global suitability ranges as a regional or farm-specific recommendation.
